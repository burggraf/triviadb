# TriviaDB Implementation Plan

> **REQUIRED SUB-SKILL:** Use the executing-plans skill to implement this plan task-by-task.

**Goal:** Build an easy-to-run, restartable CLI that converts openly licensed structured facts into original, reviewed, US-oriented multiple-choice trivia in SQLite.

**Architecture:** Source snapshots → canonical facts and provenance → deterministic answer/distractor selection → Gemini writing → separate Gemini review → approved `questions`. SQLite is both the queue and the output; transactional checkpoints and cached API responses permit restart. One writer per database, no service or vector database.

**Tech Stack:** Python 3.11+ standard library (`sqlite3`, `argparse`, `urllib`, `csv`, `json`, `hashlib`, `uuid`, file locking). No runtime dependencies.

---

## Approved design

User selected CC0/public-domain only, initially Wikidata, The Met Open Access, and Natural Earth. Do not import Jeopardy clues, noncommercial question banks, or Wikipedia prose. Keep source URL, license, record identity, retrieval time, raw snapshot, and source references separate from the requested game schema.

The public `questions` table has the requested fields: `id` (UUIDv4), `category`, `subcategory`, `question`, `a` (correct), `b`, `c`, `d`, `difficulty` (1–9), `notes` (nullable). Categories are defined in the catalog. Subcategories are broad reusable recipe/topic groups, not individual entities. Clients must shuffle options during play. Approved additional fields are `type` (`text`/`photo`/`sound`) and nullable `media_id`.

Identity is a SHA-256 fingerprint of canonical subject ID, predicate, object ID/value, and canonical semantic qualifiers, independent of wording, source, difficulty, or distractors. Cross-source Wikidata IDs are reused when available. Also reserve a subject/predicate/scope slot to prevent alternate versions of the same question and quarantine source disagreements. A normalized-text unique key catches repeated wording. No promise of perfect global semantic deduplication when sources lack shared identifiers.

Facts are not automatically treated as unquestionable truth. Reject multiple/unknown answers and unsupported qualifiers, ambiguous titles, attribution uncertainty, trivial or obscure material, and poorly supported notes. Popularity is an ingestion filter, not a guarantee of trivia quality. Reviewer checks source support, clarity, sole correct choice, plausible distractors, timelessness, American-adult relevance, and entertainment value. LLM review is not independent external fact verification. Do not silently publish unreviewed drafts.

Wikidata: small paged SPARQL discovery with cached entity API snapshots; a streaming local JSON/JSON.gz/JSON.bz2 dump importer provides the bulk path without hammering the public service. Start with immutable relationship recipes across major categories. Subject/object labels must be English. Gather all nondeprecated property claims before deciding uniqueness; skip qualified or conflicting facts. Preserve disambiguating descriptions and years.

Met: download the official CSV atomically, stream records, default to collection highlights with confident single-artist attribution. Reuse work and artist Wikidata IDs; predicate P170 matches Wikidata painting-creator facts.

Natural Earth: cache the official populated-places GeoJSON. Select recognizable cities, derive northernmost-of-four questions mathematically from coordinates, and retain all operands as evidence. Stable, nonoverlapping groups avoid an artificial explosion of nearly identical combinations.

Gemini: REST structured JSON, comma-delimited .env keys without printing or storing secrets; round-robin selection with persistent key/model cooldowns, optional project group labels, Retry-After/RetryInfo handling, daily quota reset, disabled bad credentials, bounded request budgets. Provider quotas apply per project; key count is not a quota multiplier. No billing setup or unlimited pilot run.

## Added scope: optional media (approved by user)

Add automatic Met Open Access image questions plus a local importer for explicitly licensed image/audio files. Media licenses are checked per asset, not inherited from metadata. Met requires API `isPublicDomain=true` and an Open Access image URL. Manual imports require explicit CC0/public-domain recording/image rights confirmation and license evidence. MusicBrainz metadata does not license recordings; a short clip is not automatically fair use.

Use a related `media` table for source, license evidence, creator, attribution, content hash, neutral alt text, sanitized local path, and clip boundaries. Add nullable `questions.media_id` and a fact-to-media link. Generate only one question per fact, whether text or media. The writer and reviewer receive the attachment; reject if it does not match the supplied fact. Use installed ffmpeg/ffprobe for metadata-stripped JPEGs and bounded WAV clips; these are optional system requirements for media only. Export required assets alongside SQLite. Keep attribution/revealing source metadata out of pre-answer gameplay displays, not out of provenance.

Tests cover rejected licenses, unsupported/invalid files, media-required publication, clipping bounds, safe filenames, and export asset availability.

## Added scope: quality pilots and balanced sampling

User requested a way to inspect small batches and avoid obscure/overly difficult or alphabetical/topic-heavy results. `sample` now uses seeded hashing, category/relationship balancing, repeated-subject suppression, a best-effort 60/30/10 easy/medium/hard mix, and difficulty bounds. Default generation excludes narrow specialist relationships and applies conservative prominence floors; `--include-specialist` is an explicit audit opt-in. `stats` reports distributions without claiming empirical calibration. `reject` records manual editorial rejection and removes the published question while retaining fact and prior review evidence. `set-difficulty` records a reasoned editorial override while retaining the original model review. No player telemetry or speculative adaptive-difficulty system is built.

The first live pilot exposed an overly obscure Met artwork/artist question. It was manually rejected, and editorial prompts now explicitly distinguish museum highlights from familiar pub-trivia material. Wikidata literary works use Q7725634 rather than assuming novels use P31=Q8261. Live Gemini reported 2.5 Flash Lite retired for new users; 3.5 Flash Lite + 3.5 Flash were successfully tested instead.

Independent read-only review found three reproducible bugs: blank review reasons could poison the response cache; ineligible first-page facts could hide later candidates; repeated facts could exhaust the distractor scan before distinct answers. Regression tests were added and the three issues fixed. Source HTTP rate limits now persist Retry-After cooldowns and exit safely rather than allowing immediate retries. Discovery prioritizes unvisited/least-recently-visited recipes after partial runs, preventing repeated rate limits from starving later topics. Full artwork titles are disallowed in media clues by local validation.

## Verification and pilot results

- Initial offline suite: 34 passing tests; later quality-guard changes expanded the suite to 44 passing tests; Python compile checks remain successful.
- Initial pilot baseline: 717 canonical source facts (Met 416, Natural Earth 164, Wikidata 137). Later bounded imports are resumable and are not treated as a finished corpus.
- Initial pilot: 30 attempted candidates; 16 retained after automated/editorial review, across nine categories: 15 text, one photo. Fourteen rejected candidates and their evidence retained. A subsequent 100-question quality pilot was withdrawn after user review found it too difficult and repetitive; its evidence remains auditable.
- Difficulty estimates: nine easy, five medium, two hard. Manual corrections were needed; no actual player calibration is claimed.
- Both working/export SQLite integrity and foreign keys checked; question fields, UUIDv4 IDs, media existence and SHA-256 checksums checked.
- Stable source replay did not add facts. Source/model cooldowns, draft resumption, invalid-cache recovery, and partial download handling have regression checks.
- `data/pilot.json` is the seeded preview; `data/party.sqlite` and `data/party.media/` are the reviewed export.
- Working DB 1,478,656 bytes; source cache 409,418,631 bytes; six local photos 485,086 bytes. Local storage is sufficient; S3 was not implemented.
- Configured API keys were absent from checked source, tests, documentation, SQLite databases, and sample artifacts. Root `.env` was not overwritten.
- Live text/photo generation tested; sound-file processing tested offline only. No automatic sound discovery, external search fact-checking, empirical difficulty model, or full dump download was added.

## Deliberate boundaries

No embeddings, web UI, autonomous research agent, or copying existing trivia prose. MusicBrainz, Smithsonian, and other source-specific adapters remain future additions, not claimed support. Full Wikidata dumps can require hundreds of GB; never download one automatically. Automated approval needs ongoing human sampling; absolute factual accuracy, flawless wit, and semantic uniqueness are not guaranteed.
